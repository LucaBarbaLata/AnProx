# 0003. Koin for dependency injection

- Status: Accepted
- Date: 2026-10-14
- Questionnaire: Q39 (owner is learning Android)

## Context
ViewModels need repositories, repositories need the server hub, and the hub needs storage. Something
has to construct and share these objects.

## Options
1. **Hilt** (Google's recommendation): compile-time checked, but needs annotation processing
   (KSP), generated code, and many annotations to learn.
2. **Koin**: a small Kotlin DSL, resolved at runtime, with no code generation.
3. Manual DI (an `AppContainer` class): zero magic, but boilerplate grows with every screen.

## Decision
Koin 4.1. The whole graph is one readable file (`app/.../di/AppModule.kt`).

## Consequences
- No KSP/kapt in the build, so builds are faster and there are fewer toolchain moving parts (see ADR 0002).
- A missing binding is a runtime error, not a compile error. Mitigation: every screen is opened
  during the manual checklist. A Koin `verify()` unit test can be added in M1.
- Swapping to Hilt later is mechanical, because classes take their dependencies through constructors.
